# Эксперимент по ретриву: объекты наблюдения → документы

Зачем всё это: надо числами закрыть вопрос, как искать документы под объект
наблюдения — ключевыми словами, вектором по названию объекта или вектором по
развёрнутому описанию. Полный контекст — в
`docs/architecture/HANDOFF_2026-07-28_retrieval_experiment.md`.

## Что выяснилось до начала (2026-07-29, проверено на сервере)

Три факта из проб, которые определили нынешний план:

1. **Answer key банка неприменим.** Его 72 упоминания датированы 9–13 июня,
   а обработанный корпус начинается 18 июня. Пересечения нет вообще, и
   ссылки в нём в основном ведут на story-страницы Дзена, а не на статьи.
   Значит эталон делаем свой.
2. **Тексты короткие.** Медиана `clean_content` — 709 символов, p95 — 2908.
   Спор «резать документы на чанки или искать по документу целиком» на таком
   корпусе почти теряет смысл: при чанке в ~1500 символов больше 95%
   документов дают один чанк. Семантическая нарезка остаётся в плане, но
   только для длинного хвоста, а основной осью эксперимента становится
   представление запроса.
3. **Брендов в корпусе мало, темы много.** `openai` — 8 документов,
   `anthropic` — 65, зато `\yии\y` — 944, `нейросет*` — 351. Отсюда способ
   набирать пул (см. ниже).

## Шаги

| Шаг | Что делает | Статус |
|---|---|---|
| 1 | `build_candidate_pool.py` — выгрузка кандидатов на разметку | готов |
| 2 | разметка пула по объектам → эталон | не начат |
| 3 | замер трёх способов поиска против эталона | не начат |

## Шаг 1: пул кандидатов

Пул = **широкий невод по теме ∪ ключевые слова объектов**, и это
принципиально. Если набрать пул одними ключевыми словами объектов, а потом
на нём мерить recall этих же ключевых слов, получится 100% по построению:
регекс найдёт ровно то, что сам в пул и положил. Пропуски — документы, где
объект упомянут иносказательно и ключевого слова нет, — в такую выборку
просто не попадут, а ради их измерения эксперимент и затевался.

Оба набора паттернов лежат в `patterns.py`, там же обоснование и оговорка
про точность: полностью известен только регекс объекта 1, у объектов 2–10
оригиналы в документации обрезаны, поэтому они восстановлены по алиасам и
помечены `approx=True`.

### Запуск на сервере

Скрипт только читает БД, в сеть не ходит, ничего не пишет кроме своего
выходного файла. Виртуальное окружение и `.env` берём у Агента 1.

```bash
cd /root/.openclaw/workspace/agents/agent_1
. .venv/bin/activate

# сперва без записи -- только статистика, чтобы увидеть размер пула
python /root/.openclaw/workspace/experiments/retrieval_eval/build_candidate_pool.py

# затем выгрузка
python /root/.openclaw/workspace/experiments/retrieval_eval/build_candidate_pool.py \
  --out /root/.openclaw/workspace/experiments/retrieval_eval/data/pool.jsonl
```

Полезные флаги: `--limit 200` для быстрой пробы, `--max-chars` — обрезка
текста в выгрузке (по умолчанию 6000 символов, чтобы файл не распухал).

### Что смотреть в выводе

- **общий размер пула** — ожидание порядка тысячи документов;
- **«поймано только широким неводом»** — доля документов, которые ни один
  регекс каталога не поймал. Это верхняя граница того, что ключевые слова
  могут пропускать; если тут ноль, эксперимент бессмысленен, если сильно
  больше половины — каталог к нашему корпусу почти не подходит;
- **разбивка по датам и источникам** — корпус неоднороден: 18–27 июня это
  СМИ, 28–30 июня — в основном Telegram (61% живых документов). Если пул
  окажется целиком в телеграмных днях, эталон будет смещённым.

### Формат выгрузки

JSONL, одна строка — один документ:

```
id_clean_post, time_post, source, host, url, title, text, text_len,
truncated, summary, companies_raw, matched_broad, matched_objects,
label_objects, label_source
```

`matched_*` — что сработало автоматически (это вход эксперимента, не
эталон). `label_objects` и `label_source` пустые: их заполняет шаг 2, и
именно они станут эталоном.

`companies_raw` — вендорское поле как есть. Внутри JSON-строка со словарём
`{"Сущность": ["контекст", ...]}`, заполнено примерно у 56% документов.
Вытаскиваем сущности мы сами, на это поле ничего не завязано; оно лежит в
выгрузке только как бесплатная линейка, чтобы потом сравнить с ним свой
экстрактор.

## Перенос выгрузки

`data/` не коммитится (см. `data/.gitignore`) — чтобы корпус новостей не
уехал в репозиторий случайно. Если файл понадобится перенести, это делается
осознанно: `git add -f experiments/retrieval_eval/data/pool.jsonl`.
