# Агент-фильтратор


## 1. Задача

В пайплайне есть агент-фильтратор.

| | |
|---|---|
| **на входе** | поток новостей + каталог объектов наблюдения: название, алиасы, ключевые слова, негатив-фильтр |
| **на выходе** | конечный набор документов по каждому объекту |

Две особенности, которые определяют всё остальное:

1. **Полнота важнее точности.** 
2. **Агент должен проводить границу**, какие документы передаем дальше, какие - нет.

---

## 2. Как собирали эталон

Мерить было не на чем: готовой разметки под наши объекты не существует.
Собрали свою.

### Три шага

| шаг | что делали | осталось |
|---|---|---|
| **1. Пул кандидатов** | объединили два набора: что поймали ключевые слова каталога и что поймал широкий отбор по ИИ-лексике | 2 395 |
| **2. Отсев** | выкинули документы, где тема задета вскользь — по частоте темы, без модели | 1 318 |
| **3. Разметка** | модель читает первые 4000 знаков и относит документ к объектам | 750 привязок |

### Почему пул набирали шире каталога

Это главное решение во всём замере.

Если размечать только то, что поймали ключевые слова, их полнота выйдет
**100% по построению**: регекс найдёт ровно то, что сам же в пул и положил.
Померить его стало бы невозможно.

Поэтому в пул добавили широкий отбор по ИИ-лексике — независимый от
каталога. Он и создаёт зазор:

| | привязок «документ → объект» |
|---|---|
| положительных всего | 750 |
| из них нашли ключевые слова | 322 |
| **попали в разметку другим путём** | **428** |

Больше половины релевантных документов ключевые слова не находят. Ровно эти
428 и делают замер осмысленным.

### Два уровня меток

| метка | что значит | пример |
|---|---|---|
| **событие** | новость про объект по существу | «OpenAI выпустила новую модель» |
| **упоминание** | объект назван, новость про другое | «...такие компании, как OpenAI, Google и другие» |

Мерили по событиям. Без этого разделения любое перечисление вендоров
засчитывалось бы как попадание.

### Чем проверяли сам эталон

| проверка | что делали | результат |
|---|---|---|
| **контроль** | взяли бренды, у которых нет других значений в языке (GigaChat, DeepSeek, OpenAI), и сверили с разметкой | подтверждено 119 из 121 — **98%** |
| **самосогласованность** | разметили часть выборки заново, вслепую | совпало **77%** по составу объектов |

Модели не показывали, какие ключевые слова сработали на документе. Иначе
она бы просто соглашалась с регексом, и весь замер потерял бы смысл.

Второе число задаёт разрешающую способность эталона: разницу в три-пять
пунктов он не различает, в десять — различает.

### Оговорка, которая работает в одну сторону

В знаменатель попали только документы из пула. Релевантная новость, которую
не поймали ни ключевые слова, ни широкий отбор, в замер не вошла — мы про
неё не знаем.

Такие новости почти наверняка без ключевых слов, иначе попали бы в пул через
них. Значит настоящая полнота ключевых слов ещё ниже измеренной.

**Правило: проигрыш ключевых слов доказан, выигрыш — нет.**

---

## 3. Что проверяли

Четыре гипотезы:

| № | гипотеза | вердикт |
|---|---|---|
| 1 | Ключевых слов достаточно, вектор их уточняет | ✗ **опровергнута** |
| 2 | Запросом должно быть описание объекта, а не название | ✓ **подтверждена** |
| 3 | Специализированная модель эмбеддингов даст прирост | ✓ **подтверждена** |
| 4 | Границу отсечения можно найти в самих оценках | ✗ **опровергнута** |

---

## 4. Результаты

### ✗ Гипотеза 1: ключевых слов достаточно

Ключевые слова находят в среднем **43%** нужного. Здесь важен разброс:

| объект | тип | полнота |
|---|---|---|
| OpenAI / ChatGPT | строка | 92.4% |
| Open-source модели | строка | 74.7% |
| GPU и мощности | строка | 58.6% |
| YandexGPT / Алиса | строка | 46.4% |
| Регуляторика ИИ | понятие | 31.1% |
| Внедрение GenAI | понятие | 28.7% |
| Доверие к ИИ | понятие | 13.6% |
| Инциденты и безопасность | понятие | 4.8% |

**Объекты бывают двух видов.** Про OpenAI нельзя написать по существу, не
написав «OpenAI». Про доверие к ИИ — можно, и обычно так и пишут.

Исходная схема ставит ключевые слова фильтром поверх векторного поиска.
Это пересечение, и его полнота не может превысить полноту ключевых слов:

| объект | ключевые слова | цепочка «И» | вектор отдельно |
|---|---|---|---|
| OpenAI | 92.4% | 78.6% | 85.5% |
| Регуляторика | 31.1% | 27.9% | 77.0% |
| Доверие к ИИ | 13.6% | 13.6% | 74.6% |
| **Инциденты** | 4.8% | **1.4%** | **61.4%** |

Цепочка проиграла на **восьми объектах из восьми**.

### ✓ Гипотеза 2: запрос — описание, а не название

| глубина | название | алиасы | **описание абзацем** |
|---|---|---|---|
| @100 | 39.0% | 42.2% | **50.7%** |
| @500 | 64.6% | 70.1% | **76.9%** |


### ✓ Гипотеза 3: специализированная модель

| | обычная модель | асимметричная | прирост |
|---|---|---|---|
| объекты-понятия | 44.0% | 53.5% | **+9.5** |

Весь прирост — на понятийных объектах. На брендовых его нет вовсе: там
запрос по сути строка, с ней справляется любая модель.

### ✗ Гипотеза 4: граница есть в самих оценках

Возник вопрос, как отделять то, что нужно передать дальше, от того, что можно оставить за фильтром. Отсечь по определенному значению косинуса не удалось, так как разрыва в его распределении нет — оценки убывали плавно. Детектор разрыва всегда упирался в нижнюю границу.

Границу дала LLM в роли реранкера:

> **10** — новость целиком об объекте · **4–6** — упомянут вскользь ·
> **0** — не относится

| решающее правило | полнота | точность | документов | 
|---|---|---|---|
| отсечка по косинусу | 70% | 40% | 138 | 
| кросс-энкодер | 74% | 59% | 75 | 
| LLM  | **76%** | **93%** | **44** |

Втрое меньше документов при вдвое лучшей чистоте.

## 5. Выводы

**1. Порог не ищется в геометрии.** Косинус и оценка кросс-энкодера — меры
сходства без опоры. Они говорят «эта пара похожа сильнее, чем та», и между
разными объектами несравнимы. Единого порога у них нет в принципе.

**2. Границу задаёт сформулированный критерий.** Шкалу задают слова,
одинаковые для всех объектов. Косвенное подтверждение: две разные модели
независимо сошлись на одном пороге — **7.5 из 10**.

**3. Это удобно эксплуатировать.** Рубрику можно показать заказчику,
обсудить и поправить. Порог косинуса обсуждать не с чем.

**4. Качество объекта важнее качества модели.** Один объект —
«корпоративное внедрение GenAI» — не берётся ничем. Дело не в поиске, а в
том, что формулировка слишком широкая.
