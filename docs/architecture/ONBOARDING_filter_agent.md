## 1. Что ты делаешь

Агент получает каталог объектов наблюдения и корпус новостей. Для каждого
объекта он должен вернуть **конечный набор документов** — не ранжированный
список, а решение «эти берём, эти нет».

Исследование, как это делать, уже проведено. Твоя задача — реализация, а не
повторное исследование. Разделы 3 и 4 говорят, что именно уже закрыто.

## 3. Что уже решено — не переоткрывай

| решение | почему |
|---|---|
| запрос = **описание объекта**, не название | +12 пунктов полноты; проверено, что дело не в длине запроса |
| каналы **объединяются**, не пересекаются | цепочка «И» проиграла на 8 объектах из 8 |
| глубина кандидатов **500** | на @100 полнота 51%, на @500 — 77% |
| граница = **оценка LLM по рубрике, порог 7.5** | 76% полноты при 93% точности против 70/40 у отсечки по косинусу |
| негатив-фильтр каталога — **вето поверх** решения | дешёвый и предсказуемый |

Проверено и **отвергнуто**, повторять не надо:

- **HyDE** (генерация вымышленной новости как запроса) — навязывает выдаче
  свой стиль;
- **RRF / гибридный поиск** — хуже одиночного вектора на 6 объектах из 8;
- **мультизапрос** при равном бюджете — проиграл везде, кроме одного объекта;
- **отсечка по разрыву в косинусе** — разрыва в распределении нет, детектор
  всегда упирался в защитный минимум;
- **кросс-энкодеры как решающее правило** (BAAI/bge-reranker-v2-m3,
  jina-reranker-v3) — их оценка не откалибрована между объектами, единого
  порога нет.

## 5. Что построить

1. **Поле «поисковое описание»** в контракте объекта. Спека готова, см. файл
   3 из списка чтения. Сейчас это главный рычаг качества.
2. **Векторный канал**: эмбеддинг описания, топ-500, `hnsw.ef_search` не
   меньше глубины поиска (см. пункт про грабли ниже).
3. **Лексический канал**: регексы каталога по корпусу.
4. **Объединение** результатов двух каналов.
5. **Оценка LLM по рубрике** для каждого кандидата, батчами, с кэшем по
   ключу «объект + документ + модель» и обработкой 429.
6. **Порог 7.5**, затем негатив-фильтр как вето.
7. **Регрессионный тест**: прогон на эталоне, полнота не ниже 70%. Если
   упало — сборка не годится.

## 6. Открытые вопросы — спроси, не угадывай

**Номер и границы агента.** В `agents/agent_2/` сейчас лежит другой агент:
промпт без инструментов, превращающий бизнес-цель в JSON с темами,
ключевыми словами и весами источников. В таблице пайплайна Агент 2 описан
так же. Но по концепции объектов наблюдения каталог теперь приходит от
внутреннего агента банка, то есть прежняя работа Агента 2 частично снята.
**Выясни, фильтратор заменяет agent_2, встаёт рядом или это Агент 3.**

**Куда писать результат** — в какую таблицу и в какой схеме.

**Какая LLM в проде и её бюджет.** Замеры: Opus — 93% точности, Sonnet —
84% при вдвое меньшей цене. Это решение про деньги, не про технику.

**Пересчитывать ли корпус асимметричной моделью.** Прирост +9.5 пункта, но
только на понятийных объектах. Сейчас корпус в `text-embedding-3-small`,
dims=1024.

## 7. Правила репозитория

- Не трогать `agent_1.processing_jobs` — боевая очередь.
- Не запускать `parsers360_ingest` без явного указания: это поход в сеть.
- Секреты и приватные данные не коммитить. Ключи в `agents/agent_1/.env`,
  в Git его нет.
- `trash` вместо `rm`.
- **Не нагружать CPU.** Локальные кросс-энкодеры на этой машине давали
  6.11 с/пара и клали её. Тяжёлое считать через API.
- Всё внешнее и необратимое — подтверждать у пользователя.

## 8. Грабли, на которые уже наступили

| грабля | как проявилась |
|---|---|
| `hnsw.ef_search` по умолчанию 40 | полнота не росла с ростом K, все замеры выше 40 были шумом |
| `SET hnsw.ef_search = %s` | синтаксическая ошибка, SET принимает только литералы. Нужен `set_config()` |
| кэш реранкера без модели в ключе | молча переиспользовались чужие оценки |
| OpenRouter резервирует кредит под `max_tokens` | HTTP 402 при дефолтных 65536 |
| 429 принят за фатальную ошибку | это временная ошибка, нужен пейсер и Retry-After |
| сравнение «после@50» с «до@100» | реранкер выглядел вредным, хотя выигрывал |

Общее правило: **сломанный замер выглядит как работающий.** Любая
подозрительная цифра проверяется чтением документов глазами, а не
рассуждением.

## 9. Чего в замерах нет

Чтобы ты не принял их за больше, чем они есть:

- цифры получены на подвыборке 4395 документов, корпус — 40 314;
- полнота LLM 76% считается от кандидатов топ-200, сквозная около 70%;
- LLM проверена на 4 объектах из 8;
- регексы объектов 2–10 — реконструкция, оригиналы в документации обрезаны;
- объект 8 «Корпоративное внедрение GenAI» не берётся ничем, похоже, дело в
  формулировке самого объекта;
- 9% нужных документов не попадают в кандидаты вообще, и их никто не читал.
