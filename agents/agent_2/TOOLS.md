## Известные грабли (из брифа, `docs/architecture/
ONBOARDING_filter_agent.md`, раздел 8) — не наступать заново

- **`hnsw.ef_search` по умолчанию 40.** Полнота не растёт с ростом K, пока
  `ef_search` не поднят. Устанавливать через
  `SELECT set_config('hnsw.ef_search', %s, false)` — **не** через
  `SET hnsw.ef_search = %s`: `SET` принимает только литерал и падает с
  `syntax error at or near "$1"` на параметре. Значение стоит читать
  обратно (`SHOW hnsw.ef_search`) и сверять — тихо не применившийся
  ef_search портит все числа замера, ничем себя не выдав.
- **Кэш решающей оценки без модели в ключе** молча переиспользует чужие
  оценки. Ключ кэша — всегда тройка (id_object, id_clean_post, model).
- **OpenRouter резервирует кредит под `max_tokens`.** HTTP 402 при
  дефолтных значениях (пример: 65536) — задавать разумный `max_tokens`
  явно, не полагаться на дефолт провайдера.
- **429 — временная ошибка, не фатальная.** Нужен пейсер и уважение
  заголовка `Retry-After`; падать на первом 429 нельзя — весь батч
  встанет без причины.
- **Сравнение замеров на разной глубине кандидатов друг с другом**
  (например, «после@50» с «до@100») даёт ложные выводы — реранкер может
  выглядеть вредным, хотя на самом деле выигрывает. Сравнивать только на
  одной и той же глубине.

## Design Reminders

- Каналы объединяются (`|`), не пересекаются (`&`) — цепочка «И»
  проиграла ключевым словам на 8 объектах из 8.
- Негатив-фильтр — вето **после** порога 7.5, не до и не вместо LLM-оценки.
- Связь объект↔документ — M:N. Один документ может входить в итоговые
  наборы нескольких объектов одновременно; глобальной дедупликации по
  корпусу быть не должно.
